# Build and verify the Rust Windows pages

Metis 0.5.0 supplies one Rust form/probe controller and shared page protocol in
`metis-web::embedded`. Moirai 0.9.0 owns the WebIDL bridge, permissions, native
WebView2 lifecycle and child working directory. Installed applications contain
the compiled module; the application needs the installed WebView2 runtime.

The [accepted design](../../../../../docs/adr/0059-windows-rust-pages.md) owns the
dependency graph and failure contract. Actual Windows readiness, interaction,
denial, stop/remount and installer acceptance remain pending. Historical
[native captures](../../../../../docs/manual/native/captures.md) retain their
recorded executable revisions and do not validate this Rust controller.

## Prepare before direct Windows Cargo commands

Use the repository-pinned Rust toolchain, its WASM target and the exact
wasm-bindgen CLI version selected by the lock. Build the CLI first; it does not
depend on the application executable or launch Cargo from a build script.
From the Metis workspace on Windows:

```powershell
cargo build --locked -p metis-cli --bin metis
$metadata = cargo metadata --locked --no-deps --format-version 1 | ConvertFrom-Json
$cli = Join-Path $metadata.target_directory "debug\metis.exe"
$inventory = & $cli prepare metis.json
if ($LASTEXITCODE -ne 0) { throw "Rust page preparation failed" }
$env:METIS_WEBVIEW_ASSET_INVENTORY = $inventory
cargo build --locked -p metis-app --bin metis-app
$app = Join-Path $metadata.target_directory "debug\metis-app.exe"
& $app --metis-webview 60 2 0.2
```

`prepare` prints the absolute inventory path. Without an output argument it
creates a fresh owned preparation directory under the effective Cargo target
directory. An explicit output must be a new directory. Set `WASM_BINDGEN` to an
absolute CLI executable when it is outside `PATH`; a version mismatch fails.
Reprepare after source, lock, configuration or tool changes. Native compilation
rejects stale, missing, malformed or oversized preparation.

On Windows, `metis build`, `metis package` and `metis dev` prepare the declared
module before compiling the application. `metis.json` declares:

```json
"embedded_module": {
  "package": "metis-web",
  "platform": "windows"
}
```

This is an optional native manifest field. A direct Windows `metis-app` build
requires its preparation environment, including console and framebuffer modes,
because that executable also contains the WebView2 mode. Apple packages and
ordinary browser applications keep their documented entry points in the
[Apple](../../../../../docs/manual/apple.md) and
[browser](../../../../../docs/manual/browser.md) manuals.

## Asset and configuration ownership

The CLI resolves the actual selected Cargo, rustc and wasm-bindgen executables,
uses a child-only neutral working directory and retains the repository compiler
pin. Active untracked compiler wrappers fail admission. It checks the locked
WASM release context to discover actual compiler/build-script inputs before
final code generation. Source inputs, generated inputs, declared directories,
effective Cargo environment and tool identities must remain coherent through
compilation and module generation.

Cargo's primary outputs share dependency ownership with their debug/import
companions. Preparation retains actual raw compiler records and an explicit
[typed root receipt](../../../../metis-cli/src/build/module/receipt.md);
exported dependency lists omit environment keys and cannot replace that receipt.
Explicit emission recompiles the preparation root. Ordinary browser builds keep
Cargo caching; uplifted-only nonroot dylibs without reported raw metadata reject.

`inventory.bin` records the module/export/schema, provider identities, complete
lock digest, source/configuration identities and the two generated assets.
`bindings.bin` maps those semantic owners to current local roots and tool paths;
those owner-root and tool-binding paths remain outside canonical identity.
Literal paths in effective compiler configuration remain recorded and change
inventory identity. Explicit declared
directories include every member, including nested `target` or `.git` names.
The build script independently verifies the inventory, then embeds the verified
byte buffers through `OUT_DIR`; it launches no compiler or local web server.
One `PreparedModule::open` API selects the sealed zero-sized `ProducerContext`
or `NativeContext`. Producer admission compares its current WASM selectors and
effective environment. Native admission consumes the recorded WASM configuration;
native Cargo's derived flags and Clippy wrapper belong to native compilation.
Both contexts verify the same current lock, input/configuration files, directory
membership, bound tool bytes/version/pin and retained generated bytes. The
[context owner](../../../../metis-core/src/embedded_assets/fs/context.rs)
defines this authority boundary.

Use the canonical machine-readable budget owner:

```powershell
& $cli asset-budgets
```

Its JSON fields derive from
[`metis-core::embedded_assets`](../../../../metis-core/src/embedded_assets/budget.rs):

| JSON field | Canonical bound |
|---|---|
| `portable_path_bytes` | `PORTABLE_PATH_LIMIT` |
| `records` | `FILE_LIMIT` |
| `manifest_bytes` | `MANIFEST_LIMIT` |
| `module_bytes` | `MODULE_LIMIT` |
| `payload_bytes` | `PAYLOAD_LIMIT` |

The inventory codec bounds counts, text, paths and complete encoded bytes before
admission. Each generated JavaScript/WASM asset has its own module byte bound;
the aggregate packaged payload uses the independent payload bound. These limits
do not claim bounds for private compiler or browser parser allocations.

## Native lifecycle and evidence

The [startup evidence contract](event_loop/startup.md) distinguishes actual
document navigation, pre-Ready diagnostic observations and native producer
assets from Ready admission. Diagnostic observations cannot establish a
successful application journey or extend its deadline.

The packaged form/probe contains HTML/CSS and one three-line ABI bootstrap.
Rust owns theme/command state, focus, numeric editing, Unicode submission,
backend replies, permissions and callback teardown. Generated wasm-bindgen
JavaScript remains browser interoperability.

`PageSession` requires exact source, schema, role, inventory digest, mount and
monotonic request identity. Identifiers retain every integer through canonical
decimal text; input/rate decimal strings retain the exact finite binary64 value.
The page publishes Ready only after its actual
elements, listeners, theme and native bridge exist. Backend submission preserves
the existing synchronous supervised IPC transaction; owner-thread pumping
during an in-flight backend exchange remains a separate transport increment.

[`ErrorCode`](../../../../metis-core/src/error.rs) retains its `repr(u16)` wire
layout. Its derived `NoUninit` contract admits initialized enum bytes, and
`bytemuck::must_cast` checks equal source/destination size at compilation.
The constant conversion preserves every discriminant; `from_wire` continues
to reject unknown words rather than treating every bit pattern as an enum.

Native permission admission uses the separately derived configured origin;
page-message admission retains the exact full document URL. The SDK
[permission Uri](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2permissionrequestedeventargs#get_uri)
is origin-valued. Actual provider CI reports `https://metis.invalid/` for denial
and `https://metis.invalid/index.html` for messages. Other paths, query/fragment,
hosts, schemes or ports do not enter the permission evidence set.

Close/Escape requests Stop. The actual Stopped acknowledgement requires released
application owners and reports retained settlement guards and zero-or-two realm
geolocation dispatchers. Actual queued native Destroyed follows successful
fresh-profile browser exit. The host drops native owners before removing its
owned content/profile directories. A capture remains owned bytes until these
phases succeed; only then is the PNG written and success evidence published.

The permission probe requires four actual native denial kinds and four real
browser outcomes, with one final reconciliation when native callbacks arrive
after browser settlement. Grant, API absence, timeout or an unobserved native
kind fails acceptance. Notification denied/default are distinct browser values.
The canonical predicate permits geolocation rejection code `1`, camera or
microphone `NotAllowedError`, and notification denied/default. Geolocation
unavailability/timeout and media device/track/constraint errors fail with their
original name, code and message. The [geolocation](https://www.w3.org/TR/geolocation/)
and [media request](https://www.w3.org/TR/mediacapture-streams/) standards define
these domains. A native denial can precede device selection; it proves neither
device availability nor successful acquisition.
Cancellation retains an unsettled per-document slot until real settlement or
document destruction; remount cannot replace a busy request with a false result.
Consented ordinary-browser positive grant and late-acquisition cleanup remain
separate pending verification.

Production lifecycle JSON goes to stderr; stdout remains private IPC. The
Windows gate uses actual OS/UI Automation input for the ordinary executable and
exact installed-runtime Rust fixtures for remount, malformed/duplicate/stale
commands and a genuine Submit followed by the real authorized backend. Each
fixture has a strict 60-second orchestration bound. No page evaluator or
synthetic browser bridge provides acceptance evidence.
The visible remount fixture uses three genuine submissions on the same surface.
The UI actor checks the reset result, enabled submit and closed command menu,
then observes exact computed rates before physical Escape admits Stop/remount.
The first cycle opens the command menu to verify its reset on later mounts.
These installed-runtime assertions remain pending actual Windows execution.
